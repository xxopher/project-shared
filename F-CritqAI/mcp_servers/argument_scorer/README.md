# argument-scorer MCP Server

Deterministic, rule-based scoring for student debate responses. Zero LLM tokens consumed.

## Transport Modes

### Local development (stdio)

```bash
cd mcp_servers/argument_scorer
pip install fastmcp==3.4.2
python server.py
```

Runs on stdio — ADK connects via stdio subprocess transport. No port needed.

### GCP Cloud Run (serverless HTTP)

The server auto-detects `PORT` env var and switches to `streamable-http` transport:

```bash
# Build and push to Artifact Registry
docker build -f mcp_servers/argument_scorer/Dockerfile \
  --build-context root=. \
  -t REGION-docker.pkg.dev/PROJECT/critiqai/argument-scorer:latest \
  mcp_servers/argument_scorer/

docker push REGION-docker.pkg.dev/PROJECT/critiqai/argument-scorer:latest

# Deploy as Cloud Run service
gcloud run deploy argument-scorer \
  --image REGION-docker.pkg.dev/PROJECT/critiqai/argument-scorer:latest \
  --platform managed \
  --region REGION \
  --no-allow-unauthenticated \
  --port 8080
```

The Cloud Run URL (e.g. `https://argument-scorer-xxx.run.app`) is then set as `SCORER_URL` in
the main web_app Cloud Run service's environment variables.

## Tools

| Tool | Args | Returns |
|------|------|---------|
| `score_argument(text, rubric)` | text: str, rubric: "paul_elder" | Full 4-dimension score dict |
| `score_dimension(text, dimension)` | dimension: one of 4 names | Single dimension score |
| `get_rubric_info()` | — | Metadata about scoring dimensions |

## Scoring dimensions (Paul-Elder)

Each 0–5:

- `logical_coherence` — claims follow from premises
- `evidence_quality` — concrete data vs vague assertions
- `counterargument_handling` — acknowledges opposing views
- `scope_awareness` — recognizes argument limits

## Config

Scoring thresholds are loaded from `scorer_config.json` in the project root (generated by the
Teacher Dashboard's Scorer Settings tab). If the file is absent (e.g. in the Cloud Run container),
all defaults are used — identical to the UI's default values.
